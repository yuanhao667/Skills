# 产物与字段规范

## 1. 评测目标卡

严格输出以下字段：

```text
评测对象｜决策类型｜1个核心目标｜3个核心指标｜1个一票否决项｜不在本次范围｜控制变量｜预算与时间
```

需要额外记录的信息放在“待确认项”中，不要悄悄写入已确认字段。

一票否决项使用以下结构：

```text
通过：……
不通过：……
```

## 2. 覆盖矩阵

第一轮至少包含：

```text
场景分类｜难度｜样本类型｜数量｜主要覆盖指标｜设计理由
```

矩阵下方列出：总数、各样本类型数量与实际比例、每个核心指标预计覆盖数、待裁定项。

## 3. 评测集

最终表格字段固定为：

```text
case_id｜评测对象｜场景分类｜测试输入｜难度｜样本类型｜预期表现｜硬性约束｜重点观察项｜数据来源（AI合成）｜模型输出（空）｜评分/标签（空）｜评分理由（空）｜是否Bad Case（空）
```

要求：

- case_id 稳定且唯一，后续版本不得因排序改变。
- 模型输出、评分／标签、评分理由、是否 Bad Case 初始为空。
- 数据来源统一填写“AI合成”，除非用户提供了真实数据并要求保留来源。
- CSV 使用 UTF-8；长文本、换行和引号必须正确转义。

## 4. Rubric v1

每个维度一行，字段为：

```text
维度／指标｜定义｜权重｜打分方式｜档位锚点｜正例1｜正例2｜反例1｜反例2｜易分歧点｜硬性否决线｜评分记录方式
```

Rubric 旁边单独保存可调整参数：

```text
核心维度最低分｜加权达标线｜硬性否决优先｜权重合计｜评分理由格式
```

未获用户确认的参数标注“建议值”，不得显示为冻结规则。

## 5. 四 Sheet XLSX 执行模板

用户要求可执行工作簿，或阶段 3 完成后需要交付 XLSX 时，严格使用四个 Sheet：

### 评测集

保存评测样本及空模型输出字段。评分结果可从评分工作台自动回写，但不得改变测试输入、预期表现和硬性约束。

### 评分标准

保存 Rubric v1、权重、最低分、加权达标线、硬性否决优先规则和评分记录方式。权重合计不为 100% 时突出报错。

### 评分工作台

一行对应一个 case，至少包含：

```text
case_id｜场景与样本信息｜测试输入｜预期表现｜硬性约束｜模型输出｜各维度评分｜各维度证据｜硬性否决｜否决依据｜加权总分｜单Case结论｜是否Bad Case｜评分理由/规则引用
```

人工录入区与公式区使用明显不同的底色。所有权重和门槛必须动态引用“评分标准”，不得在公式中重复写死。

### 评分汇总

在尚未评分时显示“待评分”。至少汇总：

```text
样本总数｜已填模型输出｜已评分样本｜评分完成率｜通过数量｜需迭代数量｜一票否决数量｜通过率｜各维度平均分｜平均加权总分｜评分依据完整数量
```

只有用户已经确认整体版本门槛时，才能自动输出“通过／不通过”。没有整体门槛时，只显示数据状态和最低维度，不擅自作上线结论。

## 6. 文件关系

目标卡是上游冻结输入，不必为了凑 Sheet 数放进执行工作簿。四 Sheet 工作簿用于阶段 2–3 的交付和后续评分准备：

```text
评测目标卡
  ├─> 评测集
  └─> Rubric v1
        └─> 四Sheet执行工作簿（空评分状态）
```

本 Skill 不填正式模型评分，不生成试标对齐记录，也不输出最终评测报告。
