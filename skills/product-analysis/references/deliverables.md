# 四类交付物规范

## 目录

1. 用户旅程图
2. Agent 契约拆解
3. 单 Agent 功能等价 System Prompt
4. 产品全景架构拆解

只读取用户当前选择的章节；共享证据规则以 `evidence-protocol.md` 为准。

## 1. 用户旅程图

### 目标

从最早输入到最终可见结果，说明用户想完成什么、做了什么、页面反馈什么、需要做何选择、结果是否真实产生，以及失败或中断后如何处理。

### 交付顺序

1. 本次查看范围。
2. 无法访问或无法确认的证据。
3. 用户旅程证据表。
4. 三泳道用户旅程图。
5. 用户情绪、想法与感受。
6. 痛点与用户可补充区。
7. 同类产品机会点。
8. 三个最值得讨论的体验问题。

### 用户旅程证据表字段

| 阶段 | 用户目标 | 用户动作 | 页面反馈 | 用户需要做的决定 | 页面/资产状态变化 | 问题或阻力 | 证据 |
|---|---|---|---|---|---|---|---|

“证据”必须包含页面原文、按钮名称、Agent 名称、可见资产、错误信息、截图编号和证据编号。

### 三泳道图要求

- 泳道仅为：用户、产品界面、系统结果。
- 每个节点标注证据编号。
- 包含正常主流程、用户修改/纠偏、失败与中断。
- 判断节点包括适用的“满意/不满意”“成功/失败”“继续/中断”“余额充足/不足”。
- 余额不足没有页面证据时，保留为尚未确认路径，不得画成已发生。
- Agent 说完成但画布没有结果时，在系统结果泳道标冲突。

## 2. Agent 契约拆解

### 目标

只记录本次截图中有证据出现的 Agent，整理其输入、功能判断、工具、输出、全局上下文和下游交接。不要预设 Agent 数量。

### 交付顺序

1. 查看范围与证据缺口。
2. Agent 清单。
3. 每个 Agent 的 I/O 契约卡。
4. 工具总表。
5. 全局上下文字段表。
6. 数据生产者—消费者关系表。
7. Agent 输入—判断—工具—输出—交接流程图。
8. 事实、推断和未知事项清单。
9. 最值得继续验证的五个问题。

### Agent 清单字段

| Agent | 首次出现 | 触发者 | 接替对象 | 工作阶段 | 下游对象 | 是否再调用 | 缺席步骤 | 证据 |
|---|---|---|---|---|---|---|---|---|

### 每个 Agent 的六类输入

1. 用户当前输入。
2. 用户长期信息。
3. 项目全局上下文。
4. 上游 Agent 输出。
5. 平台公共资产、知识与规则。
6. 工具或运行时结果。

每项写明来源类型、必需性、当前值、证据等级、证据编号、缺失影响。

### I/O 契约卡固定结构

1. 核心目标。
2. 触发条件。
3. 输入信息。
4. 可观察判断。
5. 调用工具。
6. 输出信息。
7. 全局上下文读写。
8. 完成条件。
9. 异常与重试。
10. 尚未确认的问题。

### 工具规则

- 官方名不可见时使用“读取项目上下文”“生成角色主图”等功能性名称。
- 每个功能性名称旁标“非官方工具名”。
- 只有资产、工具结果或状态变化能确认调用；口头计划只能记为计划。
- 工具表包含调用者、输入、可见结果、状态写回、失败、重试、扣费与证据。

### 全局上下文字段表

至少检查项目配置、剧本、角色、场景、道具、分镜、资产引用、模型、任务状态、确认状态、错误、历史版本、余额和反馈；页面没有的字段不补成事实。

## 3. 单 Agent 功能等价 System Prompt

### 前置条件

必须先让用户指定目标 Agent。完整收集该 Agent 在当前截图组的所有记录。该 Prompt 只追求功能等价，不冒充官方原文，不包含隐藏思维链。

### 交付顺序

1. 目标 Agent 的证据范围与边界。
2. 输入契约。
3. 输出契约。
4. 工具契约。
5. 状态机和 Mermaid 状态图。
6. 事实规则、推断规则、建议规则。
7. 功能等价 System Prompt。
8. 规则—证据追溯表。
9. 最小测试集。
10. 仍然无法确认的问题。

### Agent 边界问题

回答：解决什么问题、何时接管、谁触发、交给谁、哪些属于或不属于它、修改是否重触发、何时停止、何时自动继续、是否等待用户确认。

### 状态机

逐项核对 `waiting_input`、`planning`、`waiting_confirm`、`executing`、`validating`、`completed`、`failed`、`interrupted`、`retrying`、`handoff`。状态名可调整，没有证据的状态标推断或建议。

### Prompt 固定结构

把完整 Prompt 放入可复制代码框，内部顺序固定：

1. Agent 名称。
2. 角色。
3. 核心目标。
4. 任务边界。
5. 输入契约。
6. 全局上下文协议。
7. 工作流程。
8. 工具调用规范。
9. 用户确认机制。
10. 结果验证。
11. 修改与回退。
12. 异常处理。
13. 状态机。
14. 下游交接。
15. 完成条件。
16. 输出格式。

页面未知字段使用语义化占位名并标“推导设计”。工具名使用 `<生成视频工具>` 这类占位符，不编造 API 名。

### 规则等级

- 【事实规则】：页面直接支持。
- 【推断规则】：复现观察行为所需的合理补充。
- 【建议规则】：为提高稳定性新增。
- 【未知】：无法判断。

### 最小测试集

至少六项：完整输入、缺少必要输入、局部修改、工具失败、用户中断、全局上下文与页面状态冲突。字段包括测试输入、初始状态、预期判断、预期工具调用、预期状态变化和禁止行为。

## 4. 产品全景架构拆解

### 目标

把用户功能、Agent、工具、上下文、媒体资产、模型、知识、状态、计费、安全与治理放入同一套 As-Is / To-Be 架构中，同时区分已确认、推断、建议和未知。

### 交付顺序

1. 执行摘要。
2. 证据来源与证据缺口。
3. 核心功能域。
4. 端到端功能流转表。
5. 产品分层架构。
6. Agent、工具和全局上下文关系。
7. 全局上下文架构。
8. 知识与公共资产架构。
9. 模型接入与路由架构。
10. 底层架构选型表。
11. 数据实体表和 ER 图。
12. 端到端时序图。
13. 产品全景架构主图。
14. 当前架构 As-Is。
15. 建议架构 To-Be。
16. 关键风险。
17. 架构组件—证据追溯表。
18. 仍然无法确认的问题。

### 五条端到端流

同一创作任务并行描述：用户交互流、Agent 控制流、工具调用流、数据与上下文流、图片/视频/音频资产流。每步包含触发者、处理者、读取、判断、工具、结果、状态、确认门、下游和失败分支。

### 九层产品架构

1. 用户与渠道。
2. 交互与工作台。
3. 产品应用。
4. Agent 与流程编排。
5. 工具与服务。
6. 模型接入与路由。
7. 全局上下文与数据。
8. 知识与公共资产。
9. 基础设施与治理。

主图用静态横向分层卡片，不画指向连线。卡片写组件名称、职责摘要、证据等级和关键问题。交互和方向放在第 4、6、12 节。

### 全局上下文设计模板

检查 UserContext、ProjectConfig、ScriptContext、CharacterContext、SceneContext、PropContext、StoryboardContext、AssetContext、WorkflowState、BillingContext、EvaluationContext。它们是分析模板，只有页面证据支持时才能称为当前真实结构。

### 底层架构规则

对无法看到的后台实现只写：需要能力、可能选型、推荐方案、不能确认原因。不得把具体数据库、消息队列、云服务、模型网关或编程语言写成事实。

### 数据实体模板

检查 User、Project、Conversation、Agent、AgentRun、Workflow、Task、ToolCall、Script、Character、Scene、Prop、Storyboard、Asset、AssetVersion、UserConfirmation、ModelInvocation、Error、BillingRecord、Feedback。实体名均为分析模板，不代表真实表名。

### 风险最低覆盖项

- 聊天和画布状态冲突。
- Agent 口头完成但工具未完成。
- 资产成功但上下文未更新。
- 上游修改后下游未失效。
- 自动重试重复扣费或重复资产。
- 时长、风格、台词和音画同步缺少验证。
- 安全拦截、余额不足和用户中断处理未知。
- 私有资产权限泄漏。
- 模型能力或公共知识过期。
