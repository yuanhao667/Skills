# HTML 输出规范

## 目录

1. 基本要求
2. 信息架构
3. 图表规则
4. 交互规则
5. 视觉与可访问性
6. 完成检查

## 1. 基本要求

- 输出单文件 HTML，UTF-8，可本地直接打开。
- CSS 内联；必要的 Mermaid 可以使用模块脚本，但正文在脚本失败时仍可阅读。
- 标题、查看范围、证据缺口、证据图例和生成日期必须可见。
- 长表格包裹横向滚动容器；正文宽度适配 1280–1600px。
- 不显示 TODO、占位符、伪数据或未经标记的推断。
- 文件链接、截图编号和证据编号可搜索。

## 2. 信息架构

顶部依次包含：

1. 报告标题与一句话摘要。
2. 查看范围、截图数量和证据等级图例。
3. 当前交付物目录。
4. 正文表格与图。
5. 证据缺口、关键问题和下一步选择。

把完整内容直接平铺。不要用折叠、点击展开或隐藏内容来缩短页面。

## 3. 图表规则

- 用户旅程图只保留“用户、产品界面、系统结果”三条泳道。
- 判断节点使用菱形并写分支条件；必须覆盖正常、修改、失败与中断。
- ER 图和时序图可使用 Mermaid。
- 产品全景主图使用九层静态卡片：用户与渠道、交互与工作台、产品应用、Agent 与编排、工具与服务、模型接入与路由、全局上下文与数据、知识与公共资产、基础设施与治理。
- 全景主图不画跨层连线、箭头或关系网。每个卡片显示组件名、证据摘要和证据等级。
- 关系与方向放入数据流表、生产者—消费者表和时序图。

## 4. 交互规则

- 不依赖点击才能发现正文。
- 可以提供顶部锚点导航、搜索、高亮和“复制 Prompt”按钮。
- 单 Agent System Prompt 必须同时提供原生 `<pre><code>` 文本，即使复制按钮失效也能手动选择。
- 用户补充区若提供输入框，必须默认平铺，并说明内容只保存在当前浏览器或不保存。
- 不把视觉入口当作流程已完成的证据。

## 5. 视觉与可访问性

- 同时支持浅色与深色主题，保证文字对比度。
- 用文字标签和颜色共同表达证据等级，不只依赖颜色。
- 表头、卡片标题和证据编号有清晰层级。
- 响应式断点至少覆盖 840px；窄屏卡片改为单列。
- 避免大面积 Mermaid 网络图、交叉连线和需要缩放才能辨认的文字。

## 6. 完成检查

运行 `scripts/validate_report.py`，再人工确认：

- 交付章节齐全且顺序正确。
- 关键结论有 `E###` 证据编号。
- 事实、推断、建议和未知均有明确标签。
- 聊天、画布、任务和资产冲突未被掩盖。
- 页面没有折叠正文，没有占位符。
- 全景主图没有方向连线。
- Prompt 可复制，且明确为功能等价版本而非官方原文。
